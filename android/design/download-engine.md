# Download engine maintenance

The CPH2603 had yt-dlp 2025.11.12 from the bundled Android library. Two attempts at the same audio URL failed with HTTP 403 while fetching the media stream, before FFmpeg conversion. Updating through the existing official stable updater installed yt-dlp 2026.10.21. Retrying the selected failed job through the real download manager then downloaded, converted and exported a 238,320 ms MP3. A second live check read the exported file as `audio/mpeg` and re-analyzed its source successfully.

`DownloadStore` now reads the installed extractor's actual `--version` once during native initialization. Settings displays that value instead of the Android wrapper's version. It checks the official stable updater before analysis or an idle queue starts when the last check is at least 24 hours old. Manual updates remain available. The check is revalidated under the engine mutex, and queued work waits during an update; updates run while the download manager is idle. Analysis also holds the mutex while its extractor process is running. Failed network checks back off until the next daily check so the queue can continue with its installed engine. The automatic check preserves coroutine cancellation.

The native FFmpeg/Python/QuickJS wrapper remains 0.18.1. Its existing [stable updater and runtime setup](https://github.com/yausername/youtubedl-android/blob/master/library/src/main/java/com/yausername/youtubedl_android/YoutubeDL.kt) are used. The [official EJS guide](https://github.com/yt-dlp/yt-dlp/wiki/EJS) documents supported JavaScript runtimes; the inspected device bundle already included EJS, and the wrapper already configured QuickJS.

Validation includes the unit policy test for first use, the daily boundary, recent checks and clock rollback. `EngineRepairDeviceTest` requires an explicit `repairDownload` instrumentation argument identifying a failed audio job; it updates the official engine and retries that real job without replacing the library. `EngineFreshnessDeviceTest` requires `checkEngineFreshness=true`; it clears only the internal last-check timestamp, exercises normal analysis, verifies the new timestamp and reads an existing exported MP3. These live network checks are skipped without their explicit arguments. Raw logs and private library/download snapshots remain in ignored `artifacts/performance/`.

The original 95 songs and both playlists were preserved. The successful retry added one song. The older duplicate failed entry remains in history; the selected attempt was retried and completed.

Changed files: `DownloadStore.kt`, `Models.kt`, `ModelsTest.kt`, `EngineRepairDeviceTest.kt`, `EngineFreshnessDeviceTest.kt`, and this note. Debug, Android-test and Preview APK builds succeeded; the final unit run passed 22 tests. The separate live repair passed, followed by the final seven-test device suite including normal-path freshness and exported-MP3 validation.
